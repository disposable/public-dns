# Public DNS, DoT, DoQ, and DoH resolver data

Published public DNS, DoT, DoQ, and DoH resolver datasets, generated automatically from the [`crawler`](https://github.com/disposable/public-dns-crawler) submodule.

This repository is the **data/output repo**.
The crawler code lives in the submodule; this repo stores the generated assets.
CSV exports are not currently generated by the crawler.

## Contents

- `json/` - published JSON exports from the crawler (`accepted.json`, `validated.json`)
- `txt/` - published text/config exports from the crawler (`resolvers.txt`, `resolvers-doh.txt`, `resolvers-dot.txt`, `resolvers-doq.txt`, `dnsdist.conf`, `unbound-forward.conf`, `unbound-forward-dot.conf`)
- `probe-corpus/` - generated probe definitions used for validation
- `meta/` - build metadata (`build.json`) and the run-to-run `changelog.json`; the `history.duckdb` run memory lives on the `state` orphan branch
- `crawler/` - git submodule with the generator/crawler code

## Updates

Data is refreshed by GitHub Actions - daily on a schedule and manually via
the Actions tab. Candidates are validated in sharded matrix jobs, merged,
scored against run history, and committed. See
[HOW_IT_WORKS](https://github.com/disposable/public-dns-crawler/blob/main/HOW_IT_WORKS.md)
in the crawler repo for the full pipeline, scoring model, and local
reproduction steps.

## Usage

Consume the generated files directly from this repository.

For reproducible use, pin to a specific commit instead of following the latest repository state.

## Exported files

- `json/accepted.json` - resolvers that passed validation strongly enough to be accepted for normal use
- `json/candidate.json` - resolvers that are reachable but did not score high enough for accepted status
- `json/rejected.json` - resolvers that failed validation; only failed probes are retained, and `all_probes_failed` is set when every probe failed
- `json/filtered.json` - candidates removed before validation, for example duplicates, invalid endpoints, low source reliability, or historical quarantine
- `txt/resolvers.txt` - accepted plain DNS resolvers only, as `host:port`
- `txt/resolvers-doh.txt` - accepted DoH resolvers only, as HTTPS endpoint URLs
- `txt/resolvers-dot.txt` - accepted DoT resolvers only, as `tls://host[:port][#tls-name]`
- `txt/resolvers-doq.txt` - accepted DoQ resolvers only, as `quic://host[:port][#tls-name]` (DoQ is only exported as text/JSON - dnsdist has no DoQ backend protocol and Unbound has no DoQ upstream support)
- `txt/dnsdist.conf` - dnsdist backend config for non-rejected resolvers (plain DNS, DoT, and DoH sections), including candidate backends that dnsdist can still health-check
- `txt/unbound-forward.conf` - accepted plain DNS forward-zone config for Unbound
- `txt/unbound-forward-dot.conf` - accepted DoT forward-zone config for Unbound with `forward-tls-upstream: yes`
- `meta/changelog.json` - diff between the two most recent validation runs: added/removed resolver keys and status transitions

Large JSON files may be split into `*.part-XXXX.json` files to stay below repository limits. When that happens, the part files together replace the unsplit file.

Each entry carries a composite `score` (0-100), a `confidence_score`, derived
latency/history metrics, and informational `capabilities` tags - field and
scoring details are in the
[crawler docs](https://github.com/disposable/public-dns-crawler/blob/main/HOW_IT_WORKS.md#scoring-system).
